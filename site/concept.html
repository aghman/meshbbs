01 Concept

A bulletin board that survives the internet going away

meshbbs is a BBS in the 1990s sense — forums, private mail, file areas, door games, people typing at each other over a terminal. What's different is the wire underneath it: instances federate over LoRa radio at roughly a hundred bytes a second, so a BBS with no internet connection at all is a full member of the network.

The one thing that shapes everything else

Start with the airtime, not the architecture

A Meshtastic packet carries at most 233 bytes of application payload. On LongFast — the default preset, the one a community mesh actually runs — a full packet holds the channel for 2.157 seconds. That is about 108 bytes per second of theoretical goodput.

But that figure is the channel's capacity, not yours. Meshtastic uses managed flood routing: every node that hears a broadcast rebroadcasts it. So one origination costs the channel roughly R times the airtime of a single transmission, where R is how many nodes actually rebroadcast. On a well-connected mesh R is typically 3–5.

Every airtime figure in this project is therefore stated twice — what your node spends, and what the commons pays. The governor budgets the second one.

LongFast, mesh-wide ceiling of 5% of wall clock, shared evenly, R = 4.

What that budget forces

Batching is structural

One packet per post wastes the fixed header every time and burns two seconds of airtime on a forty-character message. Posts accumulate for 15–30 minutes so framing amortises and the compressor can find redundancy across messages.

No files over mesh, ever

A single 1 MB file would take over a week of channel time. Only catalogs replicate — you see the whole network's file list, and bytes move over IP or sneakernet. This is enforced in the type system, not a config toggle.

Every byte argued for

Record IDs are derived from content rather than transmitted. Node IDs and area tags hoist into a per-bundle table. Binary encoding, truncated hashes, a pre-shared compression dictionary. Not JSON, not UUIDs.

The social constraint

A shared Meshtastic channel is a commons. A BBS network that parks itself on a community mesh and eats 30% of the airtime will be — rightly — unwelcome. Note that a separate channel is not separate airtime: every channel on the same frequency slot shares the same physical medium. Channel separation buys tidiness; only the governor buys neighbourliness.

Addressing

The node ID is the key

There is no separate address, and nothing to apply for. A node's identity is the first eight bytes of the BLAKE3 hash of its Ed25519 public key: 

node_id = BLAKE3(ed25519_pubkey)[:8]        // 8 bytes / 64 bits

The property this buys is self-certification. Anyone holding a record can hash the claimed public key and check it against the ID in the header. There is no binding to maintain, no registry to consult, no authority to run — and no way to squat an identity you don't hold the key for.

An entire category of machinery disappears with it: first-seen address bindings, anti-squatting detection, a numbering scheme, a coordinator to assign numbers. None of it needs to exist, because the binding is arithmetic.

Eight bytes rather than four because the threat is adversarial rather than accidental. An attacker can grind keypairs until one hashes to a target's ID, then present forged records to peers that haven't yet learned the real key. 32 bits falls in minutes on a GPU; 48 bits in hours to days. 64 bits puts it out of reach.

Cost on the wire
None, in practice. origin hoists out of each record into a per-bundle origin table, so an 8-byte ID is paid once per bundle and each record carries a 1-byte index. Break-even against a 4-byte numeric address is three records — and batching puts normal traffic well past that.
Key rotation
Because the ID is the key, rotating means becoming a different node. A signed SUCCESSION record handles the planned case and peers auto-follow it, with four guardrails: always alert, tombstone the old ID at the effective time, one succession per predecessor, and reject implausible effective times.
A lost key
Has no recovery path, and the docs say so plainly. With no old key there is nothing to sign a succession with. You are a new node — which, because peer setup is just an ID exchange, is a handful of messages rather than a re-registration. This is the price of having no registry, and the reason there is no registry to petition.
The human problem

Nobody wants to type K7QM4X2PB9TFR

This is the real cost of key-derived IDs and it deserves a straight answer. Zooko's triangle says identifiers can be globally unique, human-meaningful and decentralised — pick two. Numeric addressing chose unique and meaningful, and paid for it with a registry. Key-derived chooses unique and decentralised. The missing leg has to come from somewhere else.

It comes from petnames, and they are a real feature rather than an afterthought. Each BBS keeps one sysop-owned alias table, exactly like Host entries in an SSH config. Users type austin@pnw and never see an ID.

Aliases are strictly local, which is why no registry is needed: two BBSes may disagree about what pnw means and neither is wrong. They resolve at compose time and never travel on the wire — putting pnw in a record would make delivery depend on the recipient sharing your private naming.

Two renderings of the same 64 bits

One identifier, two display codecs, losslessly convertible. They exist because they serve different physical channels — nobody types the words, and nobody speaks the base32.

vivid scout amber		 Reading aloud — voice radio, phone, confirming a fingerprint in person. Appears only where a human verifies an identity out of band; it is not an input method

Six words, not four: 64 bits at 11 bits per word from a 2048-word list. Four words would need a 65,536-word dictionary.

The honest trade

Routing and trust get simpler and safer; typing an unfamiliar node ID gets worse. The alias table is what hides that, and if the alias experience is weak this decision will feel bad in daily use.

Security model

Assume the whole channel is public

The mesh channel key is shared by every BBS on the network — which means every participating sysop holds it. Meshtastic's channel encryption has known limitations besides. So the mesh is treated as a public broadcast medium, and the design follows from that rather than fighting it.

  • Everything is signed, so content can't be forged or tampered with in transit, regardless of who is listening.
  • Forum posts are public by definition. There is no confidentiality expectation and the interface says so.
  • Private messages are end-to-end encrypted, so the shared channel key is irrelevant to them. They are also user-signed rather than node-signed — non-repudiation between individuals is worth the bytes.
  • Message metadata is not protected, and this is a deliberate documented trade rather than an oversight. Other sysops can see that one user messaged another, and when. It buys immediate bounces for undeliverable mail and per-recipient spam filtering.
  • Trust is not transitive. If A trusts B and B trusts C, A does not accept C's records — though A will happily relay them, because records are signed end-to-end and relaying is safe regardless of trust.
  • Local moderation always wins. A remote tombstone is honoured by default when it comes from the same node as the post it deletes, and never auto-honoured when it comes from a different one.
⚠ Amateur radio operators

If your node runs in Meshtastic's ham mode, you operate under FCC Part 97, which prohibits messages encoded to obscure their meaning. meshbbs hard-blocks encrypted private messages in that mode — and, because the channel key is also encryption, refuses to start with an encrypted channel at all.

Signing is fine. Ed25519 authenticates without obscuring anything, so the record log, node records and forum federation all work normally under Part 97. Only confidentiality is the problem. There's an override, with a self-documenting name and a banner every launch.

Scope

What it deliberately isn't

A design is as much what it refuses. These are decisions, not gaps — each was considered and turned down for a reason.

File transfer over mesh
Not a quota, not a sysop toggle, not a tiny-files exception. The mesh link refuses file payloads outright. Catalogs replicate; bytes go over IP or sneakernet.
Bluetooth LE
USB serial and TCP cover every realistic deployment, and BLE was the only dependency that would have forced cgo. Dropping it makes every release artifact cgo-free with no build tags at all.
Real-time chat between BBSes
Mesh latency runs to tens of seconds or minutes. Node chat is local; do cross-instance chat over IP.
A web forum interface
A read-only web view may come later. SSH is the product.
User-authored ANSI theme packs
Screen templates, layout manifests and per-menu artwork are out. A curated set of built-in themes plus a themes/*.toml loader for colour and glyph overrides is in.
Legacy DOS door emulation
Deferred to Phase 7 and may never ship. The modern door API is the product. Nothing depends on the DOS path.
