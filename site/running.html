04 Run a node

Four commands to a working BBS

Build it, initialise it, back up the key, serve. That gets you a complete single-node board — forums, private mail, file areas and node chat — with no radio and no configuration. Federation is off until you turn it on, so nothing you do here puts a packet on the air.

Prerequisites

What you need, and what you don't

meshbbs is pure Go with CGO_ENABLED=0 on every target. Building needs nothing but a Go toolchain; running needs nothing at all. The browser front end is embedded in the binary too, so there is no CDN and no asset build.

You need
Go 1.25 or newer to build, a machine that stays powered on, and about 50 MB of disk to start with. Linux, macOS and Windows, on amd64 and arm64.
You do not need
A database server, Node, a C toolchain, a domain name, a TLS certificate, a port-forward, an account with anybody, or a radio. Every one of those is optional and none of them is needed for a board that works.
Root, no
The default SSH port is 2222 precisely so that nothing here needs privileges. Port 22 is a choice you make later, on a host dedicated to the BBS.
A radio, later
A Meshtastic node is what makes an instance federate. It is not what makes it work. Get the board running first, then see attach a radio.
First run

The four commands

Every block below is output copied from a real run on a clean machine, not an illustration. Your node ID will differ — it is derived from a key generated on your machine in step two, and nowhere else.

Build

One binary, no build tags, no cgo variants.

$ git clone https://github.com/aghman/meshbbs
$ cd meshbbs
$ go build -o meshbbs ./cmd/meshbbs

Initialise

This generates your node key, creates the database and writes a small config file. There is no address to choose, request or register — the node ID is derived from the key itself. Drop --sysop-password-stdin and the account exists but cannot log in until you set a password with meshbbs user passwd.

Back up keys/

Before anything else, and it is the one irreversible thing on this page. A lost node key cannot be recovered: with no key there is nothing to sign a succession record with, and the instance would have to re-establish with its peers as an entirely new node, under a new ID, with none of its history attributable to it.

$ cp -a ~/.local/share/meshbbs/keys /somewhere/else/

# the directory must stay 0700 and the keys 0600 —
# the server refuses to start on looser permissions

Serve

The startup banner is the whole state of the instance in seven lines. If something is wrong with your config, you find out here rather than three days later.

Real output, paths shortenedmeshbbs serve
$ ./meshbbs serve

fog-city is up.

  node id   J9GC-7YKB-JEHCA
  ssh       0.0.0.0:2222
  themes    [classic contrast mono muted]
  guests    true
  register  open
  files     ~/.local/share/meshbbs/files (sftp)

Connect with:  ssh new@localhost -p 2222
Ctrl+C to stop.
Where things live

With no --data-dir, everything goes in the OS convention: ~/.local/share/meshbbs on Linux, ~/Library/Application Support/MeshBBS on macOS, %APPDATA%\MeshBBS on Windows. That directory holds config.toml, bbs.db, keys/ and files/. Pass --data-dir ./somewhere to any command to keep an instance self-contained, which is the easy way to try this out without touching your home directory.

Administration

Accounts, capabilities and areas

Everything the sysop terminal does is also a subcommand, so it is all scriptable — and because these work with the server stopped, they are also the recovery path when nobody can log in. 

# accounts
$ ./meshbbs user add bob
$ ./meshbbs user passwd bob
$ ./meshbbs user list
$ ./meshbbs user show bob

# new accounts cannot post to federated areas by default:
# the door is open, the shared airtime is gated
$ ./meshbbs user grant bob post_federated
$ ./meshbbs user revoke bob post_federated

# areas — new ones are local-only until you say otherwise
$ ./meshbbs area create swap --description "Buy, sell, trade"
$ ./meshbbs area federate swap
$ ./meshbbs area share swap 0.25   # cap it at a quarter of the airtime budget
$ ./meshbbs area list
Federating an area is the consequential one

area federate is the point at which posts stop being your business and start spending airtime that fifty other instances share. Nothing on this page does that by accident: areas are created local, accounts are created without post_federated, and the mesh is off entirely until you enable it. See what the budget actually is before you turn any of it on.

Configuration

A starter config, and the four lines that matter

init writes a config file that is deliberately almost empty, because almost every default is already the right answer. This is what a real board tends to set on day one — nothing here is required, and everything here is safe.

A sane starting pointconfig.toml
[node]
display_name = "fog-city"              # what peers see beside your ID
sysop_name   = "austin"
timezone     = "America/Los_Angeles"  # display only; the log is UTC

[ssh]
port = 2222                            # 22 on a host dedicated to the BBS

[users]
registration_mode = "open"            # open | approval | invite | closed
guest_enabled     = true              # ssh guest@ browses read-only
$ ./meshbbs config check   # validate before restarting — an unknown key is an error
$ ./meshbbs config show    # effective values, after defaults, file and environment
