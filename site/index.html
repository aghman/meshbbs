01 The constraint that shapes everything

The link is brutally small

A Meshtastic packet carries at most 233 bytes. On the default LongFast preset, one full packet occupies the channel for 2.157 seconds — and because Meshtastic floods, every node that hears a broadcast rebroadcasts it. One transmission costs the commons roughly 4× what it costs you.

Share a 5% airtime ceiling across fifty instances and each one gets about 21 seconds of transmit time a day. Ten full packets. That is the budget every other decision in the design answers to.

Three things fall straight out of it. Batching and dictionary compression are load-bearing requirements rather than optimisations. File transfer over mesh doesn't exist as a code path at all — only catalogs replicate. And every byte on the wire has to justify itself, which is why record IDs are derived rather than transmitted and node IDs hoist out into a per-bundle table.

No addresses to register

A node's ID is its key — BLAKE3(pubkey)[:8]. Self-certifying, so there is nothing to squat, no binding to maintain and no authority to run.

Petnames, like an SSH config

Sysops name peers locally: austin@pnw. Two BBSes may disagree about what pnw means and neither is wrong. No alias ever goes on the wire.

Sysops can't read your mail

Private messages are encrypted under a key only your passphrase opens — subject lines included. The server stores ciphertext.

And now, in a browser

Not a terminal emulator in a web page. A screen is a typed description of what you're looking at, and two renderers consume it — one draws ANSI, one builds DOM. So the browser wraps a post at a readable measure instead of column 78 and shows an area name in full instead of cutting it at 26 characters, while the terminal stays byte-for-byte what it was.

One navigation model, so a screen cannot exist over SSH and be missing from the web. You get a node number and show up in Who's Online next to everyone else. Sign-in is a passkey — no password, and no nick to type.

03 Sync & protocol

BSMP — five layers, one job each

Everything replicable is an immutable, signed record in one append-only log. Reconciling two instances is a version-vector problem, and because records are immutable, forums have no merge conflicts at all — an edit is a new record, a delete is a signed tombstone.

L4
Records
POST, DM, NODE, SUCCESSION, FILE, TOMBSTONE. Signed by the node rather than the user — a 64-byte signature is 27% of a packet, so dual-signing every post is unaffordable. Private mail is the exception.
L3
Replication
Version vectors and anti-entropy digests. Fifty nodes broadcasting every 30 minutes would eat 11% of the channel, so digests carry rolling hashes only — and 95% of scheduled beats are suppressed because they would carry no news.
L2
Bundle
Records batched over a 15–30 minute window and compressed with a pre-trained zstd dictionary. Generic zstd manages 1.3× on a short post; a trained dictionary gets 3–5×.
L1
Fountain coding
One broadcast serves every listener, each missing a different random subset — so there are no NACKs and cost is flat in audience size. Symbols 0…K−1 are the original fragments, so a clean link decodes at zero coding overhead.
L0
Datagram
A Meshtastic MeshPacket on a dedicated channel. No packet carries identity bytes at all; node-to-radio bindings are learned from a signed announcement, on demand.

Why a fountain code, measured

Symbols needed at K=10 and 15% loss. ARQ wins at a single receiver — which is why unicast repair to one lagging peer is still the right move — but its cost grows with the audience while the fountain's doesn't.

04 Run a node

One binary, no runtime

Pure Go with CGO_ENABLED=0 on every target. No database server, no Node, no C toolchain — Linux, macOS and Windows on amd64 and arm64, from one build matrix.
