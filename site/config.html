Configuration

One TOML file, strictly validated

An unknown key is a startup error, not a silently ignored line — because quietly dropping airtime_ceiling_pct when somebody wrote airtime_ceiling_percent is how a mesh gets flooded. Almost every default is already the right answer, so a good config file is a short one.

Mechanics

Where the file is and how it wins

meshbbs init writes config.toml into the data directory. You can keep it somewhere else with --config, and put the whole instance somewhere else with --data-dir — both are global flags accepted by every subcommand.

Default location
~/.local/share/meshbbs/config.toml on Linux, ~/Library/Application Support/MeshBBS/ on macOS, %APPDATA%\MeshBBS\ on Windows. meshbbs config check prints the path it actually read.
Precedence
Defaults, then the file, then MESHBBS_* environment variables, then command-line flags. Later wins. Every setting has an environment variable — mesh.hop_limit is MESHBBS_MESH_HOP_LIMIT — which is what makes container deployments possible without a config file at all.
Only differences
A key you do not write takes its default. There is no 400-line commented dump to maintain, and no way for your file to drift behind a new release.
Unknown keys are fatal
A typo does not start. Neither does an out-of-range value, a web.enabled without an origin, or a ham-mode combination that would break Part 97. Cross-field checks live here rather than scattered through the code.
Changes need a restart
Today, all of them: stop serve and start it again. A SIGHUP reload for the subset that can be applied live — themes, MOTD, rate limits, quiet hours — is in the design and is not built yet, so do not assume a running instance has picked up an edit.
Real output, paths shortenedmeshbbs config check
$ ./meshbbs config check
Configuration OK: ~/.local/share/meshbbs/config.toml
  data directory: ~/.local/share/meshbbs
  database:       ~/.local/share/meshbbs/bbs.db
  keys:           ~/.local/share/meshbbs/keys
  environment:    production

config check exits non-zero when it is unhappy, which is why the generated service units run it as a pre-start step: a BBS that fails to start beats one that starts with the wrong airtime budget. config show prints the effective values after precedence, and config reference prints every key there is, generated from the source so it cannot drift.

Recommended

Three configs you can copy whole

Pick the one that describes your board. Each is complete — everything not written here is left at its default deliberately, not by omission. 

# A board for you and people you know. No radio, no web, no
# public port. This is the shape most instances should start in.

[node]
display_name = "fog-city"
sysop_name   = "austin"
timezone     = "America/Los_Angeles"

[ssh]
bind = "0.0.0.0"
port = 2222

[users]
registration_mode = "closed"   # you create the accounts yourself:
guest_enabled     = false      #   meshbbs user add bob

[log]
level = "info"
# Open to strangers over SSH and in a browser. The origin and the
# certificate are the only two things without sensible defaults.

[node]
display_name  = "fog-city"
sysop_name    = "austin"
sysop_contact = "austin@example.com"   # published in your NODE record
timezone      = "America/Los_Angeles"

[ssh]
port         = 22                     # needs root or a capability
max_sessions = 32

[users]
registration_mode       = "open"     # ssh new@ works; federated
guest_enabled           = true      #   posting is still withheld
session_time_limit_mins = 0         # 0 = no limit; sysops exempt

[web]
enabled  = true
origin   = "https://bbs.example.com"    # REQUIRED — passkeys bind to it
port     = 8443
tls_cert = "/etc/meshbbs/fullchain.pem"
tls_key  = "/etc/meshbbs/privkey.pem"

[log]
level  = "info"
format = "json"
file   = "/var/log/meshbbs/bbs.log"
# Everything above, plus the radio. Read the airtime page before
# you set mesh.enabled: this transmits on a band other people use.

[mesh]
enabled       = true
mode          = "serial"          # serial | tcp | auto
serial_device = "/dev/ttyUSB0"    # empty auto-detects; see `mesh ports`
channel_name  = "bbsnet"          # same name and key on every instance

hop_limit     = 3                 # as low as your topology allows
quiet_hours   = "22:00-06:00"     # local time; may wrap midnight

# The two numbers that decide your budget. Leave both alone until
# `meshbbs mesh survey` has told you what R really is on your mesh.
airtime_ceiling_pct     = 5       # the WHOLE network's share, not yours
expected_instance_count = 50      # what divides it
flood_multiplier        = 4       # R — a guess until you measure it

# Over WiFi instead of USB:
#   mode     = "tcp"
#   tcp_host = "meshtastic.local"   # port 4403 if you omit it
registration_mode is not fully built

Only open is distinguished today: it is what lets ssh new@ register an account. approval, invite and closed all currently do the same thing — they refuse self-registration — because the approval queue and the invitation flow are not written yet. Use meshbbs user add in the meantime, and read closed as "the honest name for what the other two do".

Orientation

What each section is for

Nine sections, and most boards touch three of them. The full reference lists every key in each with its default and its environment variable.

[node]
Who this instance says it is: display name, sysop name and contact, timezone, and whether it is a development or production instance. There is no node_id key — the ID is derived from the key in keys/ and is read-only everywhere.
[storage]
Where the data directory, database, file areas and keys live. The keys directory must be 0700 with 0600 keys or the process refuses to start.
[ssh]
The front door: bind address, port, session cap. On by default, because a BBS with no way in is not one.
[users]
Registration mode, guests, session time limits, and whether new users are listed in the network directory. Note that new accounts never get post_federated, whatever the registration mode.
[web]
The browser front end. Off by default and the only section with a required key — see below.
[telnet]
Off by default, and guest-only when on. Telnet is plaintext: browsing over it costs nothing, typing a password over it costs everything.
[mesh]
The radio link and the airtime governor. Off by default because turning it on transmits on a shared band. Every key here is explained on the radio page, in the order you need them.
[theme]
Default theme and encoding, and the directory scanned for *.toml style overrides. A malformed theme file is a startup error, never a silent fallback.
[log]
Level, text or JSON, and a file to write to. Empty logs to stderr, which is what you want under a service manager.
The second door

Turning on the browser front end

The web UI is served from the same binary — no CDN, no asset build, nothing to deploy separately. It is off until you give it two things it cannot guess: the origin browsers will reach you at, and a certificate.

Set the origin exactly

Scheme, host and port as the browser will send them. Passkeys are bound to this string, and getting it wrong does not degrade — every sign-in fails with a browser error that says nothing about the cause. That is why it has no default and is validated at startup.

Point at a certificate

Any normal chain and key. The exception is loopback: browsers treat http://localhost as a secure context, so a bind to loopback needs no certificate — which is the easy way to try the web UI before you own a domain.

Check, then restart

config check catches a missing origin before you find it at the sign-in page.

$ ./meshbbs config check
$ ./meshbbs serve
  ssh listening on :2222 · web listening on :8443

Get your first passkey across

Press P in an SSH session and type the code it shows into the sign-in page. The code is short-lived on purpose — it is read off a terminal and typed into a browser on the same desk, so ten minutes is generous.

Behind a reverse proxy

web.trusted_proxies is empty by default, which means X-Forwarded-For is ignored and every request is attributed to the address it arrived from. That is correct when nothing sits in front of you, and it collapses every per-client rate limit into one shared allowance when something does. Set it only for proxies you run: any address listed there can claim to be any client.

Sharp edges

The settings that repay reading twice

Most keys are inert if you get them wrong. These are the ones that either fail invisibly or cost somebody else something.

web.origin
required when enabled
Wrong value, total failure, no useful error. There is no partial credit here.
mesh.hop_limit
0 — use the radio's own
A direct multiplier on what everything you send costs the mesh. Set it explicitly, as low as your topology allows. What it actually costs →
mesh.flood_multiplier
4
R, the number every airtime figure scales linearly with — and 4 is a guess. It is not a knob to tune; it is a measurement to take, with meshbbs mesh survey.
mesh.airtime_ceiling_pct
5
The share of the channel the whole BBS network should use, divided by expected_instance_count to get yours. Raising it takes airtime from everyone else on the frequency, which is why the code clamps it at 15 whatever you write.
mesh.ham_mode_override
Set to i_accept_part97_responsibility to transmit encrypted traffic while the radio reports a licensed operator. Part 97 prohibits obscuring the meaning of amateur transmissions; the licence at risk is yours. Note what is not restricted: signatures authenticate without obscuring, so a ham-mode instance federates public traffic normally and gives up only private mail over the mesh.
telnet.enabled
false
Plaintext. Anything typed can be read by anyone on the network path. If you want it, leave telnet.guest_only at true.
web.unlocked_idle_timeout_mins
10 — vs 30 idle
Shorter on purpose. A session with mail unlocked holds the passphrase in memory, and a closing browser tab is a far less reliable goodbye than an SSH disconnect.
node.environment
production
The meshbbs dev subcommands refuse to run against a production datadir. Set development only on an instance you are willing to lose.
The asymmetry, stated

A knob whose wrong value harms other people on the mesh does not get to be a plain config value. The governor's ceiling is configurable up to a hard maximum compiled into the binary; the flood multiplier can be pinned only for testing, and logs a warning at every startup when it is; mesh file transfer is not configurable at all, because it does not exist as a code path. Sysops get wide latitude over their own instance and narrow latitude over shared airtime.
