Where the project is

Status and roadmap

Phase 3 is code-complete: a usable single-node BBS, the sync protocol and its simulator, federation over IP, and the Meshtastic link with its airtime governor, ham-mode safety checks, mesh survey, and file catalog replication — file areas whose listing travels the mesh while the files themselves never do, at any size.

Precision

Two things "code-complete" should not be read to include

What has run on real radios is the link. A full record sync between two instances over the air has not been recorded yet — the protocol is exercised exhaustively in the deterministic simulator, and that is a different claim.

And the airtime governor still runs on a guessed flood multiplier of 4. Every airtime figure in the design scales linearly with it. mesh survey exists precisely to measure the real number, and nobody has yet — including, so far, us. If you run one, the report is designed to be shared.

Roadmap

The phases

0 — Skeleton ✓
Config loader, SQLite schema, node key and ID, alias table, command tree, account CLI, injected clock and seeded RNG, CI cross-compiling all five targets cgo-free.
1 — Single-node BBS ✓
SSH server, signup, capability grants, the terminal interface, themes, local forums and mail with passphrase-wrapped keys, file areas over SFTP, node chat, the sysop panel.
2 — Federation over IP ✓
Record log, version vectors, anti-entropy, bundle format, zstd dictionary, the fountain codec, succession records, the deterministic simulator and its property, invariant and fuzz suites.
3 — Meshtastic link →
In progress. Serial and TCP transports, protobuf framing, the airtime governor with flood-multiplier accounting, ham-mode safety checks, file catalog replication, the mesh survey and live R estimation.
4 — Doors
The modern door API and its capability model, PTY and ConPTY bridging, sandboxing, reference doors. Independent of federation.
Web front end ✓
Shipped out of order, ahead of the phase it was scheduled in. The screen model was split from its rendering, then a browser renderer, passkey auth and a session bridge were built on top. It arrived as a semantic terminal rather than the xterm.js stopgap originally planned — see using it.
5 — Reach
What's left of it: inter-BBS door events, sneakernet bundles, and the client-held key helper.
6 — Interop
Freeze the wire format, publish a spec and conformance vectors, request a registered Meshtastic port number, ship the FidoNet gateway. The first point at which the project makes promises to strangers, and not to be rushed toward.
7 — Legacy DOS doors
A DOSBox-X bridge. Nice-to-have; may never ship, and nothing depends on it.
Bring-up

What real radios taught

The first two-radio bring-up has run: two Heltec V3s on a bbsnet channel, with discovery, broadcast in both directions and attribution all working. Two things came out of it that no amount of simulation would have produced.

Packet IDs are part of the wire contract, so a deterministically seeded node goes silent after a restart — it reissues IDs the mesh has already seen and every packet is dropped as a duplicate. And firmware 2.5+ encrypts unicast with the destination's own key, so a direct packet to a peer whose key you have not exchanged is acknowledged by the firmware and never reaches the application.

Honesty

Known gaps a sysop will actually hit

Things the documentation would otherwise let you assume. None of them stop a board working; all of them will surprise somebody if they are not written down.

Config reload
Not built. Every change needs a restart of serve, including the ones the design marks as hot-reloadable.
Registration modes
Only open is distinguished. approval, invite and closed all currently refuse self-registration — the approval queue and invitation flow are not written. Use meshbbs user add.
Federation over IP
The transport is built and tested — mutually-authenticated TLS with the node key as the certificate — but there is no configuration surface for pointing an instance at a peer's host. It is present in the code, not available to a sysop.
Peer access control
No allow list or block list. On the mesh, the channel key is the access control. Peering →
Succession
The record type exists and replicates; there is no CLI to issue one. A lost node key is unrecoverable today.
R is still a guess
The default flood multiplier of 4 is a placeholder in every shipped binary. It is the largest single source of error in every airtime number the project quotes.

Nearly every measured number on this site — convergence times, channel utilisation, the coding overhead constants, the publish ceiling — came out of the deterministic simulator rather than a whiteboard. Several of them contradicted what an earlier draft of the design assumed, which is the whole reason it exists. How that is built and enforced is a contributor's concern rather than a sysop's: docs/testing.md.
