03 Sync & protocol

BSMP — five layers, one job each

The BBS Sync over Mesh Protocol. Everything replicable is an immutable signed record in one append-only log, and reconciling two instances is a version-vector problem. The whole thing is designed against a 233-byte MTU — design for the mesh and you get IP for free, not the other way round.

L4 · Records

One append-only log

Everything that replicates — posts, private mail, node metadata, file catalog entries, deletions — is an immutable signed record in a single log. 

Record {
  id        [16]byte   // BLAKE3(canonical_body)[:16] — DERIVED, NOT TRANSMITTED
  origin    [8]byte    // BLAKE3(node_pubkey)[:8] — HOISTED to a bundle origin table
  seq       varint     // per-origin monotonic sequence
  ts        varint     // delta from the bundle's base timestamp
  type      uint8      // POST, DM, PROFILE, NODE, SUCCESSION, AREA, FILE, …
  area      [4]byte    // truncated hash of area name — HOISTED to bundle header
  parent    [16]byte   // threading, flag-gated so top-level posts don't pay
  body      []byte     // zstd-compressed with a shared dictionary
  sig       [64]byte   // Ed25519 over everything above
}
The ID is never sent
It's BLAKE3(canonical_body)[:16], and the receiver recomputes it from fields it already has. An earlier draft put it on the wire — 16 wasted bytes, 7% of a packet, per record. Content addressing still gives free deduplication, which matters because a flood mesh delivers the same record by several paths; the ID just doesn't need transmitting to do that.
Origin, area and base timestamp hoist
Bundles are per-area and usually single-origin, so the 8-byte node ID and 4-byte area tag are paid once per bundle while records carry a 1-byte index and a small delta. This is what makes 8-byte self-certifying IDs cheaper than 4-byte numeric addresses at any bundle size of three or more.
Immutable, with tombstones
Forums have no merge conflicts at all. An edit is a new record with a supersedes pointer; a delete is a signed tombstone. Whether a BBS honours a remote delete is local sysop policy.
The node signs, not the user
A 64-byte signature is 27% of a mesh packet, so dual-signing every post is unaffordable. Node-signing means "the instance holding this key vouches that this user posted this" — the FidoNet trust model. Private mail is user-signed, where non-repudiation actually matters and volume is low.

Three ways to silently break every signature

Found while auditing the test strategy. All three are architectural constraints from day zero rather than later hardening — each is cheap to design in and effectively unfixable once a network has history.

Freeze the canonical encoding

Verifying a signature means reconstructing the signed bytes exactly. Store records decomposed into columns and re-serialize to verify, and any encoder change — a field reorder, a varint tweak, a migration — invalidates every historical signature at once. The original signed bytes are stored verbatim and verified against; the encoder is a frozen artifact with its own version byte and conformance vectors.

Never range over a map

Go randomizes map iteration order deliberately. An encoder that walks a map produces different bytes on different runs, hence a different record ID and a signature that verifies on the machine that made it and nowhere else. This is the single easiest way to introduce a heisenbug that only appears in federation — so it's a lint rule with a property test behind it.

Sequence numbers must never regress

The subtle one. Version vectors mean a peer that has seen sequence 500 from you will never ask for 450–500 again. Restore a week-old backup, reissue those numbers with different content, and the divergence is permanent and silent — no error, no conflict, peers simply hold different records under identical coordinates forever. The high-water mark is fsynced on every advance, and an incarnation counter in the node record tells peers when a regression was detected at startup.

Two load-bearing abstractions

Link is the federation transport. Meshtastic is just one kind: a datagram link with a 233-byte MTU, 108 B/s, high loss and multi-minute latency. IP is another with a 1400-byte MTU and megabytes per second. Sneakernet — export a bundle to a USB stick — is a third, and the FidoNet gateway a fourth, with the unusual property of being a trust boundary as well as a transport.

Transport is how we reach the local radio. Serial and TCP speak the same protobuf stream, so it's a thin layer over a four-byte frame header.

L3 · Replication

The safety net should be idle

For each area a node tracks the highest contiguous sequence it holds from every origin. At fifty instances that's 500 bytes per area — three mesh packets — and across ten federated areas, 5 KB. Fine to hold, impossible to broadcast routinely.

An early draft proposed a digest broadcast every 15–30 minutes. At fifty instances that is fatal:

530 min1.1%
2030 min4.5%
5030 min11.2%

11% of the channel for control traffic carrying no content — more than the entire 5% budget, before a single post is sent.

Five mitigations, all required

  • Digests never carry full vectors. Per area, a digest carries an area tag, a rolling hash and a count — ten bytes. Ten areas is one packet. Full vectors are exchanged unicast, on demand, only once a hash mismatch proves divergence.
  • The interval scales with peer count, clamped so control traffic stays under a configured share of the budget. At fifty nodes that lands around five hours. The clamp is derived from bytes, airtime and the flood multiplier rather than chosen, so it's the number to reason about.
  • Digests piggyback on any bundle already in flight, so a node with normal traffic almost never sends a standalone one. The standalone digest is genuinely just the idle-node heartbeat.
  • Suppression. Hear a digest from a peer whose hashes match yours across every shared area, and skip your own — it would carry no information.
  • Reply suppression. One broadcast digest heard by fifty peers who are all behind produces fifty simultaneous unicast requests to one node — the digest storm wearing a different hat, and the reply is bigger than the digest that triggered it. So a peer waits a random fraction of a window before asking and drops its request entirely if the answer arrives first. Because responses are broadcast, the first peer to ask answers everyone.

A node offline for a week comes back, broadcasts a digest with stale hashes, and peers backfill it. There is no session, no handshake, and no state machine that can wedge — which is exactly why anti-entropy beats a FidoNet-style polling session here. Mesh links are far too flaky for sessions.

The number to design around

Against the 5% federation budget, the whole network can publish about six records an hour — roughly 144 a day shared across every instance and every area. Note the 1.39% floor at one record per hour: anti-entropy and per-record framing cost something even when almost nothing is being said. This is also why batching isn't optional; those figures are for one record per bundle, and amortising framing is what moves the ceiling.

L1 · Coding

Erasure coding, not retransmission

The reasoning is broadcast asymmetry. A mesh broadcast reaches every listening BBS at once, and each one misses a different random subset. Under retransmission, N receivers send N different negative acknowledgements and the sender retransmits the union — cost grows with peer count, which at fifty peers is exactly the wrong scaling.

Under a fountain code the sender emits encoded symbols and each receiver decodes as soon as it has collected enough of them. One transmission serves everyone and there is no acknowledgement traffic at all. On a link where a retransmit round-trip costs minutes, removing the round-trip entirely is worth more than the coding overhead.

Why not an off-the-shelf RaptorQ

Block sizes here are tiny — a typical bundle is 1 to 10 symbols and rarely more than 30. The classic ~5% overhead figures assume K in the hundreds or thousands; below K=20 the degree distributions those codes rely on behave poorly and overhead can exceed 20%. RFC 6330 RaptorQ also carries patent declarations, which is worth checking before it lands in an MIT-licensed binary.

Writing it as a small LT code with a tuned distribution is a few hundred lines, avoids the licensing question, and — the actual reason — lets the distribution be tuned against the simulator. Which is what caught the next two things.

Dense rows, not sparse
An earlier draft called for degree 2–3, which is correct for belief-propagation decoding — it needs sparse rows to peel. We decode by Gaussian elimination, which wants the opposite: dense rows are far likelier to be independent of what the decoder already holds. Measured at K=40, sparse needed 14.41 symbols beyond K; uniform-half needs 1.72. At mesh airtime that's minutes per bundle.
Bundle IDs from content
An earlier draft drew them at random per node. That livelocks under the governor: when a transmission is interrupted partway, a random ID makes the retry a different block, so every symbol receivers already hold becomes worthless. Measured at a 0.1% duty cycle — 30 simulated days, 43 minutes of airtime, zero records delivered. Deriving the ID from the bundle's content makes an interrupted transmission resumable; the same run then converged in 58 seconds of channel time.
Repair is a common path
Sizing targets one receiver's decode probability at about 98%. The chance that every receiver decodes is that raised to the audience size, and it falls off fast: 97% for one receiver, 79% across ten, 29% across fifty. So roughly two thirds of broadcasts leave somebody short — and that's the right trade, because sizing for fifty would inflate every transmission to spare one straggler a unicast. It just means repair requests are engineered as a routine rate-limited path, not an exception handler.

L2 · Bundle

A dictionary is worth three times the network

Generic zstd on a 400-byte forum post manages maybe 1.3–1.5× — there isn't enough data for the compressor to build a model. zstd with a pre-trained dictionary on the same post typically gets 3–5×, because the dictionary already holds common English fragments, BBS vocabulary, quoting conventions and structural boilerplate.

At ten originated packets a day, tripling effective throughput is the difference between 25 posts a day and 8. It is free range and the design takes all of it. The dictionary ships embedded in the binary and versioned; nodes announce which ones they hold, and old dictionaries stay supported.

Compression is applied to the bundle rather than to individual records, so cross-record redundancy gets captured too — which is a second reason batching earns its place.

Decompression bombs

A 233-byte packet can expand to gigabytes, and this is a trivial attack for anyone holding the channel key — which the threat model assumes is everyone. The decompressed output is hard-capped, enforced inside the streaming decoder rather than checked afterwards, and a breach is treated as a peer-quota violation worth alerting the sysop about.

Civic infrastructure

The airtime governor

The most important piece of civic infrastructure in the system, and a first-class feature rather than a nice-to-have. It is a token bucket sized in mesh airtime-seconds: per-packet airtime from the Semtech formula, multiplied by the estimated flood multiplier to get what the commons actually pays.

Charge per packet, not per byte

Airtime is affine in payload — a large fixed cost plus a linear term — so per byte it is strongly sublinear: 436 ms for a one-byte payload against 9.3 ms per byte for a full one. A byte-denominated budget therefore doesn't under-price large packets, it wildly under-prices small ones. 233 bytes in a single packet costs 2.16 s; the same 233 bytes sent one byte at a time costs 101 s. A chatty protocol can stay inside a byte budget and still take the channel apart.

  • A ceiling expressed as a mesh-wide share, default 5%, hard-capped in code at 15%. That's what the BBS network as a whole should consume; a node's own allowance is the ceiling divided by the expected instance count, which it learns from the node roster.
  • Sysops never have to compute this. The first-run wizard and the status screen show the derived figure in human terms: "your share: about 11 full packets a day, or 25 short posts."
  • Read the radio's own telemetry. Meshtastic reports channel utilisation and transmit utilisation. Above about 25% channel use, back off exponentially; above 40%, transmit nothing but already-queued private mail.
  • Respect regional duty cycles. EU 433/868 is limited to 10% over a rolling hour and firmware enforces it — so track it locally and queue rather than getting rejected.
  • Priority classes. Control traffic beats private mail, which beats forum posts, which beats file catalogs. Under backpressure, drop from the bottom. There is no mesh-file class because there are no mesh files.
  • Quiet hours, and per-area sub-budgets so one chatty area can't consume a node's whole allocation. Per-peer inbound quotas stop a rogue or malfunctioning BBS flooding you, with an alert when one exceeds them.

R is a guess, and every budget scales with it

The flood multiplier defaults to 4. If the real value on your mesh is 8, every airtime figure in the design is twice as generous as it should be. It's also the one parameter that cannot be derived, simulated or reasoned about — it's a property of a specific mesh's RF topology at a specific moment, so it has to be measured.

The trick that makes measuring it easy: Meshtastic reports both how long your node spent transmitting and how busy the channel was. Measure ambient busy-ness while transmitting nothing, measure again under a known load, and attribute the difference to your own packets and their echoes. 

R ≈ (channel_utilization_load − channel_utilization_baseline) / air_util_tx_load

meshbbs mesh survey automates it. It runs without a BBS — just a radio, no database, no SSH server, no config beyond the device connection — so someone curious about hosting can measure their mesh before committing to anything. It self-governs the load phase, refuses to run if the channel is already busy, aborts if it gets busy mid-test, sweeps the hop limit across 1/3/5 to show what hop limit costs the commons, and reports the derived budget in the units a sysop actually needs.

The other transports

Same protocol, different physics

Because the sync protocol was designed for the mesh, the other links come nearly free — but each inverts something that's true on the radio, and the governor needs to know which.

IP · TCP + TLS 1.3
Mutually authenticated with self-signed Ed25519 certificates pinned to node IDs. No PKI is needed because node IDs are already self-certifying — a certificate whose key hashes to the expected ID authenticates that node completely. The certificate is a container, not a credential: nothing checks dates, issuer or subject, since expiry would imply a renewal process that can't exist without an authority. Inbound is default-closed; a link with no allow list accepts nobody, because a listener that accepts any node dialling it is an open relay.
Broadcast costs N here
On the mesh one transmission reaches everyone, which is the entire reason for the fountain code. Over IP a broadcast is N separate sends, so the link reports broadcast as not free — and a governor reading that knows the fountain economics don't apply and unicast repair to one lagging peer is cheaper. IP is also reliable, so repair symbols are redundant and a caller can skip them.
Sneakernet
Export a bundle to a USB stick. It's a link like any other, and it's how files reach a site with no IP route.
FidoNet gateway
Echomail maps onto posts, netmail onto private messages, message IDs onto record IDs. Unusually, it's a trust boundary as well as a transport: FidoNet mail is plaintext and unsigned, so records entering are signed by the gateway's key and displayed as gateway-attested rather than author-attested. It's also the single most dangerous feature for the airtime budget — one busy echo can exceed the whole network's daily output — so it's IP-side by default and bridging an echo to mesh is an explicit per-area opt-in with a hard sub-budget.
Phase 6 — not yet built

The FidoNet gateway and the wire-format freeze land together, and in that order: gatewaying into a format that is still changing is how you generate angry FidoNet sysops. Phase 6 is the first point at which the project makes promises to strangers.
